# Sprint 1 status

Implementation branch contains PostgreSQL SQL migrations, pooled `pg` client,
Better Auth configured with its direct PostgreSQL adapter (no ORM), long-lived
365-day sliding sessions, group membership/invite service, server actions and UI.

## First-run local configuration

1. Install pnpm 10.17.1 and Node 22.
2. Run `pnpm install --no-frozen-lockfile` while the dependency lock is refreshed.
3. Copy `.env.example` to `.env.local` and provide actual PostgreSQL credentials,
   `BETTER_AUTH_SECRET`, and `BETTER_AUTH_URL`.
4. Create an empty PostgreSQL database.
5. Run `pnpm db:migrate` twice to verify idempotency; then `pnpm dev`.
6. Test sign-up, sign-in, group create, inviting another user, expiry and sign-out.

## Verification and remaining release blockers

- **Dependency lockfile resolved:** `pnpm-lock.yaml` has been generated by pnpm 10.17.1,
  committed and both CI workflows use `--frozen-lockfile`.
- **CI:** main lint/typecheck/unit/build and PostgreSQL integration workflows passed for commit `cd0403dea46ba482dfb2d97e0fb62064185194bd`.
- **Auth schema:** compare migration SQL against actual installed Better Auth 1.7.7
  model schema in CI; never auto-sync/drop production tables.
- **Passwords:** sign-up currently supports email/password only. Password reset,
  verified email, production rate limits and account recovery need completion
  before opening untrusted public registration.
- **Invites:** do not log link tokens; they are bearer secrets. Revoke/rotate
  invite support should be added before broad rollout.
- **Group finances:** removing members must be restricted after obligations
  exist; Sprint 1 has no financial ledger yet.
- **PWA:** production HTTPS and installed-app cookie persistence must be tested
  on iOS and Android.
- **Not production-ready until real-device PWA, end-to-end browser flows, abuse controls, email/password recovery, and deployment secrets are verified.**
